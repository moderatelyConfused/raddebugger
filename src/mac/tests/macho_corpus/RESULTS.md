### Remaining failures and known limits

* `swiftprog-O`, `inline_types`: 60 of 268 sites have no type. Their origins are Swift functions directly under `DW_TAG_module` (`count.get`, `map`, nameless closures), which get no function type as procedures either (56 of 84 `swiftprog-O` procedures are untyped; all struct methods are typed): a pre-existing gap of the type pass, not an inline-site matter.
* Row merging heuristic: a statement row with the line and file of the row that began the current run does not begin a new row (`rdi_from_dwarf.c`, "determine if we need a new row"). In `rustprog-debug` the line program attributes `[0x257c8, 0x25804)` to `alloc.rs:113` while only `[0x257f0, 0x25800)` lies in the `dealloc` site, so the trailing `[0x25800, 0x25804)` keeps `alloc.rs:113` in `shrink_unchecked`'s table instead of `deallocate`'s call line 725. The checker mirrors the rule; a better rule would have to know whether a row's line belongs to the caller or to the inlinee.
* Not checked: locals (locations, types), type nodes beyond the inline sites' kinds, unwind info, the x86_64 slice of the universal binary (`--arch x86_64` compares against that slice, but radbin converts the arm64 one).
